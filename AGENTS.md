The lead (Fable, in Claude Code) plans, reviews and commits; OpenCode agents `executor` (edits) and `audit` (read-only) do delegated work via `.agents/skills/opencode-subagents/run.sh`. ## Commands

```bash
pnpm bench -- --chart line --impl bklit --n 1000   # single benchmark run
pnpm bench -- --all                                 # full matrix (4 charts × 2 impls × 3 n)
pnpm bench:report                                    # regenerate docs/BENCHMARKS.md from bench/results/
pnpm qa -- --chart line --impl-a bklit --impl-b migrated --n 1000   # visual parity QA
pnpm qa -- --chart line --self-test                  # determinism self-check (same impl, same gate 0.1%)
pnpm dev:app                                          # start bench/app dev server (port 5199)
pnpm build:app                                        # production build of bench/app
cd showcase && npm run dev                        # showcase app (port 5200) — all chart pages render bklit + migrated directly
```

Bench harness uses port 5199; QA harness uses port 5198. Both auto-build `bench/app` if needed, and both auto-start/stop `vite preview`. Reuse an already-running server by passing `--base-url`.

`bench/app` has its own `package.json` and dependencies. Run its commands from that directory (`npm run dev`, `npm run build`, `npm run preview`).

## Architecture

- **`repos/`** — read-only clones of `bklit-ui` and `tanstack-charts`. Never modify files here.
- **`migrated/charts/`** — migrated chart implementations (TypeScript). Each chart exports a React component matching bklit's public API. Internal helpers in `migrated/charts/internal/`.
- **`packages/`** — source-only wrapper packages (`@showcase/bklit-charts`, `@showcase/migrated-charts`) consumed by `showcase/` via `file:` deps + `transpilePackages` + tsconfig `paths` (pattern from bklit-ui's own Next apps; LOG D89). `showcase/` is a standalone npm app (Next 15, port 5200) — run its commands from `showcase/`.
- **`bench/app/src/scenarios/`** — one scenario file per chart per impl (e.g., `bklit-line.tsx`, `tanstack-line.tsx`, `migrated-line.tsx`). Each exports a React component mounted at `#chart-root` and exposes `window.__benchPaintDone`, `window.__benchSettled`, `window.__benchUpdate()`.
- **`research/`** — Phase 1: `research/phase-1/` (inventories, stack comparison, metrics `04`, gate specs `05`) + Phase 2: `research/phase-2/` (native deep-dives `bklitui-native/` + `tanstack-native/` + forward topics). Phase 1 is frozen; see `research/README.md`.
- **`docs/phase-7/PROGRESS.md`** — source of truth for migration status (wave board, discovered work, idiom checklist). Update after every item.
- **`docs/phase-7/LOG.md`** — chronological decision log. Append, newest last. Format: `D<num>` entries, continuous across phases.
- **`docs/phase-7/BENCHMARKS.md`** — auto-generated by `bench/report.mjs`. Hand-edit only the header above `<!-- BEGIN GENERATED BENCHMARK TABLES -->`.
- **`archive/`** — earlier phases' plans, research and docs. Read-only reference.

## Key conventions

- **OpenCode agents do bulk work** (`executor` edits, `audit` reads). Fable (the lead) reviews every diff, commits, runs verification, and makes final rulings on waivers and gate failures. Agents omit failures in their reports — re-run the item's "done when" count yourself before committing.
- **All chart implementations in `migrated/charts/` must pass Q1+Q2+G1–G4** to be marked `approved` in PROGRESS.md. Gates defined in `research/phase-1/05-qa-and-benchmark-gates.md` (pre-freeze `research/05`) and summarized in `docs/PROGRESS.md` footer.
- **Waivers require explicit Fable ruling** logged in `docs/phase-7/LOG.md`. Common waiver classes: M3a/M3c vsync-floor (G1 ≥20% unreachable when B−T ceiling < 2 frames), native TanStack reconciler floor exceeds bklit (D16 precedent), headroom-floor where B−T < a few ms.
- **bklit BarChart is degenerate at n≥1000** — negative bar widths, massive console errors. Gates for bar run at n=100 only.
- **M1b (settle time) is parity, not improvement** — bklit's ~1100ms reveal is an intentional design feature the migration preserves.
- **QA hover tooltip detection** uses `.ts-chart-tooltip` selector for TanStack impls, falls back to text-length heuristic. `TOOLTIPLESS_CHARTS` in `qa/screenshot.mjs` skips tooltip assertion for charts with no tooltip (polar family, funnel, gauge, sunburst).
- **QA pixel gates**: 0.5% differing pixels for bklit-vs-migrated, 0.1% for self-test (same impl two loads).
- **Harness scenarios** query-param format: `?impl=<bklit|tanstack|migrated>&chart=<name>&n=<int>`. Scenarios must expose `window.__benchPaintDone`, `window.__benchSettled` (promise), `window.__benchUpdate()` (returns ms). Live-line scenarios also expose `window.__benchLiveTick()`.
- **Decimation**: bklit uses LTTB. Always apply bklit's own decimation strategy to `migrated` scenarios (some charts decimate, some don't; check source).
- **Bench app path aliases**: `@tanstack/react-charts` and `@tanstack/charts` resolve to `repos/tanstack-charts/packages/*/src/index.ts` via Vite aliases. bklit impls import from `repos/bklit-ui/packages/ui/src/charts/`.
- **Bench/QA scripts time out at 600s** on Bash — split long runs per-size, don't batch.

## DO NOT

- Modify files in `repos/`, `bench/run.mjs`, `bench/report.mjs`, or `qa/screenshot.mjs` without explicit gate-author (Fable) approval. These are protected harness files.
- Hand-edit generated benchmark tables in `docs/BENCHMARKS.md` below the markers.
- Add chart-specific workarounds to the benchmark harness to make numbers look better.
- Call `element.getAnimations()` per-element after bulk CSS mutations — forces quadratic whole-document animation-state flushes (candlestick D25 lesson).
