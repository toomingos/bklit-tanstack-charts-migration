## 0. Goals and rulings

Two claims to make true, in this order:

1. **TanStack native.** Every chart is a `defineChart` definition rendered by the package. Nothing inside the chart `<svg>` is written by migrated code. Stylesheets style; definitions behave.
2. **Seamless swap.** Same component API as legacy bklit: same exports, same props, same composition contract, same failure modes.

## 2. Insights: why five moves instead of forty fixes

Six audit passes produced a growing list of gaps (`00` §2–3, `05` §1–5). Read together they are not forty independent problems; they are symptoms of four decisions taken early in the migration, and each decision has one native replacement in the package. That is the case for a multi-vector plan: fix the decision once and the symptoms close as a column.

**Insight 1 — the package already emits everything a runtime context needs; we never captured it.**
`RendererChart` hands out `onRender({ container, scene, surface, interaction })` (`react-charts/dist/RendererChart.d.ts:19`, `charts/dist/dom-types.d.ts:112-117`) and `onFocusGroupChange(points)` (`dom-types.d.ts:192-194`). `scene.scales` is a `Record<string, ResolvedScale>` with `map`, `invert`, `bandwidth`, `ticks`, `viewport` (`types.d.ts:603-612`). Because no module stored that context, every chart rebuilt d3 scales beside the package's (`06` §0: 22 `.range(` sites), children could not be real components (`05` A-1..A-3), `ChartProvider` and the hooks were "genuinely absent" (`00` §3.2), and optional layers were imported statically by the parent because there was nowhere else to register a mark (`02` B-3, `04` §2). One host module fed by those two callbacks (`01` §3 route A1) is the common fix. This is also how the package's own React adapter is meant to be used: the docs' controlled-inspection example stores `context.interaction` from `onRender` and drives focus from app code (`docs/guides/interactions-and-selections.md`, "Controlled point inspection").

**Insight 2 — hover was reimplemented because polar/geo lack a `states` option, but the scene layer already resolves `states` for any mark.**
`states` is a field of `InitializedMarkBase` (`types.d.ts:672-675`) and `scene.js:187-197` wraps *any* initialized mark carrying it in a `states:` group; `resolveMarkStateScene` binds nodes to points by key prefix (`mark-state.js:6-52`, `scene-point-ownership-internal.js:10-17`). Only the option types (`RadialArcOptions`, `PolarOptions`, `GeoShapeOptions`) omit it. D424 accepted the fidelity loss as an upstream limit; it is a typing gap. The package's own precedent for attaching a field post-initialize is `whenFocused` (`focus-mark.js:1-11`, eight lines). With `states` restored, the remaining hover machinery (own polar hit-test, hover bus, `setAttribute` springs, HTML date pill, the D472 renderer gate that existed to avoid DOM-side hover writes) has a single public replacement: `pointer: false` + `interaction.resolvePointer` + `setControlledFocus` (`dom-types.d.ts:35-37`), with the package's exported polar strategy `focusGroupAngle` (`polar.d.ts:6`, PR #90). One ownership change, seven gaps.

**Insight 3 — every element we paint inside the surface has a definition-level primitive; the exceptions were consumer defs, not bklit paint.**
`createMark` may emit `group{clip}`, `rule`, `polyline{path}`, `area{path, points, polygons}`, `dot`, `rect`, `label` (`types.d.ts:848-923`), and `motion()` morphs `area` nodes that carry `points` (`motion.js:1093`). That covers the funnel (`02` N-a, upstream case `125-sales-funnel` is `areaX` + `text`), pattern hatch as clipped stripe polygons (`02` N-b), and loading placeholders (`00` N11). Linear gradients and clips are spec fields (`ChartSpecBase.gradients`, `.clip`, `types.d.ts:400-406`; stops take `opacity`, `:363-367`), which removes every zero-size `<svg><defs>` host. Package layouts exist for the three charts that carried their own: `geoShape` (`geo.d.ts:43`), `sankeyDiagram` (`network-sankey.d.ts:113`, `docs/examples/networks-and-hierarchies.md`), `sunburst` (`hierarchy-sunburst.d.ts:57`). Motion that looked like it had no primitive (the wipe reveal) is what `motion({ initial: 'always' })` does by construction: it grows bars, lines and areas from the baseline and sweeps arcs, which is how upstream reproduced the Bklit entrance in catalog case `112-motion-entrance` (`docs/reference/motion.md`, `benchmarks/motion/README.md`). Framer keyframe arrays survive because the tween clamps progress, not the easing output (`motion.js:2711-2718`). What is left, patterns, radial gradients and the animated sweep, is what the package cannot declare at all (upstream F-259, `API-FRICTION.md`), so it goes through the single seam of R10 and the issues I4/I5 rather than through polygon imitations. Hence the invariant in R3 is absolute for the chart svg, with one named seam beside it.

**Insight 4 — the package ships no CSS by design, so a stylesheet is native; behavioural CSS is not.**
There is no `.css` in the dist; styling is class names plus `--ts-chart-*` variables and the `theme` spec field (`types.d.ts:356-362`, `docs/guides/themes-and-styling.md`). Our `styles.css` has 52 selectors on `ts-chart__*` classes, which is the intended surface. The three `@keyframes` and the pre-hide rules are the part that does what a definition should do (`01` §1 W1 vs `03` §1). That split is the rule in R3 and the reason V3.6 is an audit, not a deletion.

**Insight 5 — the evidence gap is structural, so it is a vector, not a chore.**
The package renders headlessly (`renderChartSvg(scene, options): string`, `svg.d.ts:2`), which makes rest-state snapshots and scene invariants a Node test (`03` §6); `motion-dom` exports framer's `spring` as a pure generator, so both sides of transient parity are analytic (`04` §1). Nothing in `qa/` executes a chart today (`05` E-3) because the gate was designed around screenshots before those facts were on the table. Building V4 alongside V1–V3 is what lets each vector land with proof instead of rulings.

**Insight 6 — "native" has a written definition upstream, and it is an ownership table.**
`docs/reference/dom-host.md` splits responsibilities into what the definition owns (`focus`, `keyboard`, `tooltip`, `svgAnimation`, `spatialIndex`, `maxFocusDistance`) and what the host owns (measurement and `ResizeObserver`, keyed reconciliation, enter/exit animation, pointer and keyboard, `idPrefix`, `ariaLabel`); `docs/framework/react/adapter.md` "Core boundary" says the adapter redefines none of it. Native means nothing is owned twice. Checked against that table (`09` §1, ten invariants), the migrated code owns four things twice that `00`–`06` never flagged: sizing (own `ResizeObserver` fed back as `width`, which disables the host's, `use-container-size.ts:101`, 13 charts, zero `initialWidth`), server output (definitions return `undefined` until a client width exists, `area-chart.tsx:1146`), motion (zero definition-level `svgAnimation`, a hand-gated `motion()`/SVG renderer switch on all 16 mounts) and dense-data focus (zero `spatialIndex`, `maxFocusDistance: Infinity` on every cartesian chart, which is the real reason the D472 gate exists). The same table decides the shadcn question: shadcn keeps one API over Radix and Base UI by fixing names, tree and `data-slot` values and letting the engine own everything behind them (`09` §4, the two chart files are byte-identical); upstream's migrating guide says the same in "Know what not to migrate". Parity is a contract of names, tree and slots; nativeness is the ownership table; the two never compete.

**Why the order V1 → V2 → V3.** V1 changes the files V2 and V3 must edit (parents, carriers, scales); doing it first avoids merging two rewrites of `area-chart.tsx`. V2 removes the hover code that V3's motion work would otherwise have to keep compatible. V3 deletes the helpers that dominate the bundle overshoot (`02` §4: `internal/{motion-renderer,enter-transition,deferred-reveal,hover-geometry,native-tooltip}` ≈ 923 lines), which is why V5 is a measurement step at the end rather than work of its own. Every route above is inside the pinned package; nothing waits on upstream, and the two issues in `07` are asks that would let us delete wrappers, not prerequisites.
