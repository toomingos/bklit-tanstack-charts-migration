### 1.5 Reference integration pattern (verified demo, `apps/web/components/docs/profit-loss-line-demo.tsx` / `registry/examples/profit-loss-line.tsx`)

```tsx
<ProfitLossLegend align="center" hoveredIndex={legendHoveredIndex} onHoverChange={setLegendHoveredIndex} />
<LineChart data={chartData}>
  <Grid highlightRowValues={[0]} horizontal />
  <Line curve={curveLinear} dataKey="pnl" fadeEdges={false} showHighlight={false} stroke="transparent" strokeWidth={0} />
  <ProfitLossLegendHoverProvider hoveredIndex={legendHoveredIndex}>
    <ProfitLossLine dataKey="pnl" />
  </ProfitLossLegendHoverProvider>
  <XAxis />
  <ChartTooltip indicatorColor={...} rows={...} />
</LineChart>
```

Two load-bearing details, both file:line-verified and both feed **Open Ruling 2/3**:

1. **`ProfitLossLegend` renders OUTSIDE `<LineChart>`** — it is a plain HTML sibling, not a chart child. Zero SVG/TanStack surface.
2. **A transparent, zero-width `<Line dataKey="pnl">` is required as a sibling of `<ProfitLossLine>`** to register the shared y-domain and power the tooltip's nearest-point lookup — `line-chart.tsx:71-80` (`LINE_DOMAIN_EXCLUDED_NAMES`) explicitly excludes `"ProfitLossLine"` from domain registration, so `ProfitLossLine` alone never contributes to `yScale`'s domain; it only *reads* the domain that the invisible `Line` established. This is bklit's real, load-bearing API shape — not an oversight to "fix".
3. **`ProfitLossLegendHoverProvider` wraps `<ProfitLossLine>` as a JSX child of `<LineChart>`.** bklit's own `Children.forEach(children, …)` in `time-series-chart-shell.tsx:433` only iterates the *literal top-level elements* passed as `children` — it does not recurse into arbitrary wrapper components. `chart-child-passthrough.ts:22-30` (`resolveChartChildElement`) only unwraps components explicitly tagged `CHART_CLIP_PASSTHROUGH` (used for e.g. visibility wrappers), and `ProfitLossLegendHoverProvider` carries no such tag. This works in bklit because `Children.forEach`'s per-child *classification* (defs/preOverlay/postOverlay/clipExcluded/underlay via `chart-child-passthrough.ts:54-110`) falls through to the **default preOverlay bucket** for an unrecognized component name — and once React actually *renders* that bucket, the Provider mounts and its child (`ProfitLossLine`) ends up in exactly the right DOM position, because a Context.Provider contributes no DOM node of its own. bklit's domain/lines-registration logic never needs to "see" `ProfitLossLine` at all (point 2 explains why). This is a real conflict with the migrated codebase's `CHART_ROLE` convention (`children.tsx:27-35`, used for `ProjectionLine`/`LineSeriesTerminalMarker` in initiative 7), which extracts config by walking direct children and Fragments only (`plan-loop-1.md` initiative 7, ruling 6: "Fragment unwrap"). See **Open Ruling 2**.
