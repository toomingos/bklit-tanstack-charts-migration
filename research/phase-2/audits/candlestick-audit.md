# Candlestick Audit — migrated/charts/candlestick-chart.tsx

## 1. Summary
Migrated Candlestick renders OHLC data as two custom `createMark` rect groups (`wicks` + `bodies`) inside a TanStack `defineChart` → `<Chart>` shell — the marks themselves are fully custom (no stock `rect`/`link`) after a D85.1 revert from stock `link` lines, making it the only one of the four charts with zero stock marks. The split is ~20% TanStack-native (spec lifecycle + reconcile keying) vs ~80% custom (local `scaleUtc`/`scaleLinear` with `ChartScale` inset, per-candle WAAPI/CSS spring reveal via `candle-spring.ts`, native `pointermove`+bisector hover bypassing `focus`, `XAxisOverlay`/`YAxisOverlay` HTML overlays). Overall overhead verdict: **high and largely justified as GAP** — custom marks are the documented TanStack `link+rect` composition alternative but were reverted for pixel parity, while hover/reveal/axis layers duplicate stock capability at the same scale as bar/scatter.

## 6. Prioritized remediation candidates

1. **Replace two custom marks with stock `rect`/`link`/`rule` if pixel concession acceptable** — What to change: try `rect(indexedRows, { x:'x', y1:'low', y2:'high', width:WICK_WIDTH_PX })` + `rect(indexedRows, { x:'x', y1:'open', y2:'close', width:bodyWidthPx, fill: group=>pos?posFill:negFill })` and compare screenshots at n=100 and n=1000. What it becomes: no custom marks; `ChartPoint`s from stock marks drive hover without separate chrome point calc. Expected gain: **maint** (remove 110-line custom mark + `parseIdx` fragility) + **design** (stock marks are TanStack's documented composition). Risk: D85.1 revert happened because `<line>` round caps failed QA — rect may still fail at tiny bodyWidth; verify via `docs/bench` screenshot diff. Verification: QA settled + hover-30/50/70 at n=100/1000 pixelmatch <0.5% with stock marks.

2. **Wire hover to TanStack `focus: 'group-x'` + `onFocusGroupChange`** — What to change: delete native `pointermove` listener (`candlestick-chart.tsx:579-661`) and `hoverInputsRef`; let TanStack resolve nearest x via `focus:'group-x'` (one point per group sharing x), and have `attachCandlestickHoverChrome` consume `ChartPoint[]` where `group` is date ms and `yValue` is close. What it becomes: `defineChart({ focus:'group-x', maxFocusDistance:Infinity })` with real callback body. Expected gain: **maint** + **perf** (no per-move `getBoundingClientRect` + `scale.invert` + bisector). Risk: TanStack `group-x` groups by exact `xValue` timestamp; candlestick dates are unique so grouping is 1:1 — semantics match, but `maxFocusDistance Infinity` must remain or off-chart hover clears unexpectedly. Verification: hover-30/50/70 at n=100/1000 vs bklit.

3. **Consolidate x/y ChartScale hatches to single responsive builder** — What to change: derive both scales inside responsive `defineChart((ctx)=>({ x:{scale: scaleUtc().domain([minTime,maxTime])}, y:{scale: scaleLinear().domain(yDomain)} }))` where `ctx` carries `width/height`; stash ranged instances there for hover readback (or read `scene.scales` in `onRender`). What it becomes: no local `slotWidth` double-compute, no independent `heightPx`/`yAxisTicks` local duplicate, no `parseAspectRatio` string parse (`candlestick-chart.tsx:475` `parseAspectRatio` → numeric `aspectRatio` prop). Expected gain: **maint** (remove 80 lines) + **perf** (single range truth). Risk: responsive builder reruns per size change; verify `minTime/maxTime` stable. Verification: screenshot band positions unchanged; hover dot y unchanged.

4. **Gate reveal fast path robustly; add epsilon to bounce compare** — What to change: `useCssRevealFastPath = Math.abs(enterBounce-DEFAULT_ENTER_BOUNCE)<1e-6` instead of `===`.
