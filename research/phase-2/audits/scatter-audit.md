# Scatter Audit — migrated/charts/scatter-chart.tsx

## 1. Summary
Migrated Scatter uses one stock `dot` mark per series (`migrated/charts/scatter-chart.tsx:311-328`) plus fully TanStack-native `defineChart` → `<Chart>` lifecycle, but sizing, scales, axes, hover, and reveal are all custom layers. The split is ~30% TanStack-native (mark definition + reconcile) vs ~70% custom imperative chrome (spring dims, WAAPI per-circle reveal, manual ResizeObserver, HTML x-axis overlay). Overall overhead verdict: **high but partially justified** — `xRangePadding` ChartScale and per-datum gradient fills are deliberate parity/performance choices, while hover bypass and WAAPI reveal duplicate stock TanStack focus/animate at measurable cost.

## 6. Prioritized remediation candidates

1. **Wire TanStack focus back in; remove manual pointermove listener** — What to change: keep existing `bisectDateLeft`+`resolveNearestIndex` math but move it into a `ChartFocusStrategy` `{ resolve, group, navigation }` passed as `focus` option, and have `attachScatterHoverChrome` consume `onFocusGroupChange` instead of native `pointermove`. What it becomes: `defineChart(definition, { focus: scatterFocusStrategy })` where `scatterFocusStrategy.resolve` implements the same bisector strict-`>` tie-break. Expected gain: **maint** (single hookup, no SVG discovery, no ref triplet, no gradient sibling ordering hazard) + **perf** (TanStack reuses spatial path, no per-move `querySelector`). Risk: must replicate `maxFocusDistance: Infinity` and `group-x` semantics exactly; verify n=10000 hover-30/50/70 QA still passes. Verification: `qa/screenshot.mjs` hover fractions at n=100/1000/10000 vs bklit; bench M2 hover jank unchanged.

2. **Replace WAAPI per-circle reveal with single `clipPath` or TanStack `animate`** — What to change: `handleRender` current 80-line per-circle loop → one `clipPath="inset(0 100%→0 0%)"` on `.ts-chart__marks` (as `area-chart.tsx:394-396` does) or `animate:{ duration:500, easing:'ease-in-out' }` and let `reconcileChartSvg` tween `opacity`/`filter`. What it becomes: ~5 lines, zero `Animation` objects. Expected gain: **perf** (20k/40k `Animation` allocations removed; M1a mount→paint at n=10000 currently pays deferred but still-present setup loop) + **maint** (shared pattern with other charts). Risk: loses per-circle `leadingEdge` stagger (bklit's `revealDelay`); staggered fade may be deemed design-required. Verification: bench M1a at n=100 and n=10000 before/after; QA settled screenshot pixelmatch <0.5%.

3. **Consolidate sizing to `<Chart width/height/aspectRatio>` and remove manual ResizeObserver** — What to change: accept optional `width` prop, pass through to `<Chart width={width}>`; remove `useState(width)` + `ResizeObserver` effect; compute `innerWidth` from `useMeasure` or adapter-reported size. What it becomes: isomorphic sizing per `research/phase-2/tanstack-native/01-load.md` `currentWidth()`. Expected gain: **maint** (one sizing path across all charts) + **perf** (no duplicate RO). Risk: managing `innerWidth`-dependent `xRangePadding` scale without `width` state requires responsive `defineChart` builder `(ctx)=>spec` variant. Verification: screenshot outer width unchanged; bench M1a stable.

4. **Fold gradient marker technique into TanStack `gradients` spec field** — What to change: move `gradientDefs` from sibling 0×0 SVG into `defineChart({ gradients: gradientDefs, ... })` so `renderChartSvgWithResources` scopes IDs via `idPrefix`. What it becomes: `gradients` array passed to `Chart` with `fill: url(#gradId)` references. Expected gain: **design** (ID scoping via `idPrefix` per `research/phase-2/tanstack-native/01-load.md` §Theme/margin `idPrefix` sanitized) + **maint** (no DOM-order fragility). Risk: TanStack currently only resolves gradients for certain nodes; verify `dot` `fill: url(...)` resolves. Verification: two scatter instances on one page — no ID collision; hover unaffected.

5. **Remove duplicate yScale ChartScale hatch; stash via definition builder** — What to change: derive `yScaleD3Ref` from same `scaleLinear` instance passed to `defineChart` by using responsive builder `defineChart((ctx)=>({ y:{scale: sameScale} }))` where scale is created inside builder and stashed there. What it becomes: no second `ChartScale.resolve` wrapper. Expected gain: **maint** (25 lines removed). Risk: low. Verification: hover dot y pixel unchanged at n=100.

6. **Gate `yGradient` feature explicitly or implement it** — What to change: add `yGradient` prop to `ResolvedSeries` or document as out-of-scope pilot gap. What it becomes: either `linearGradient` defs variant with `gradientUnits="userSpaceOnUse"` per `research/phase-2/inventory/01-bklit-ui-inventory.md` §2.5, or explicit WONTFIX. Expected gain: **design** (API completeness). Risk: none. Verification: storybook `yGradient=true` renders vertical red→emerald blend.
