# Line Audit — migrated/charts/line-chart.tsx

## 1. Summary
Migrated Line uses one stock `lineY` per series (`migrated/charts/line-chart.tsx:158-167`) plus fully TanStack-native `defineChart` → `<Chart>` lifecycle, but sizing, y-domain, axes, hover, and reveal are custom layers wrapping the host. The split is ~35% TanStack-native (mark definition + reconciled path) vs ~65% custom imperative chrome (ResizeObserver, decimation, HTML axis overlays, `attachHoverChrome` springs, WAAPI clip reveal). Overall overhead verdict: **moderate-high and partially removable** — decimation + `xForIndex` mapping are deliberate parity choices, while manual sizing, overlay axes, and hover bypass duplicate stock TanStack guides/focus at measurable maintenance cost.

## 6. Prioritized remediation candidates

1. **Replace WAAPI clip reveal with TanStack `animate`** — What to change: `handleRender` WAAPI `marks.animate({clipPath})` → `defineChart({ animate: { duration: animationDuration, easing: REVEAL_EASING } })` and rely on `reconcileChartSvg` `d` enter tweens; drop `bkmRevealed` dataset guard. What it becomes: zero imperative DOM queries, one declarative option, shared with bench M1a budget. Expected gain: **maint** (single reveal path across all charts) + **perf** (no `Animation` object, no `querySelector`). Risk: loses one-time clip wipe vs per-path `d` interpolation; verify wipe vs morph visual difference is acceptable. Verification: bench M1a at n=100 before/after; QA settled screenshot pixelmatch <0.5%.

2. **Adopt TanStack native guides for at least one axis** — What to change: remove `XAxisOverlay` or `YAxisOverlay` and set `x: { scale: scaleUtc, guide: true, ticks, format }` or `y: { guide: true }`; delete `x-ticks.ts` tick search for that axis. What it becomes: `createChartScene` auto margin + tick layout, no HTML overlay sibling. Expected gain: **maint** (removes `x-axis-overlay.tsx:116`/`y-axis-overlay.tsx:127` + `x-ticks.ts:284` combinatorial search) + **perf** (no extra HTML layer, no `MAX_GAP_LAYOUTS=400` search on data change). Risk: guide typography may diverge from bklit clamp; data-aligned tick evenness may differ. Verification: QA guides screenshot diff; bench TTP at n=1000 (tick search is bench-visible per inventory §7 hot spot #5).

3. **Consolidate sizing to `<Chart width/height/aspectRatio>` and debounce** — What to change: pass `aspectRatio` numeric to `<Chart aspectRatio={parseAspectRatio(aspectRatio)}>` and remove manual `useState(width)`+`ResizeObserver`; use `initialWidth` for first paint; add 10 ms debounce to remaining observer if kept. What it becomes: isomorphic sizing per `research/phase-2/tanstack-native/01-load.md` `currentWidth()` + `mountChartRenderer` observer. Expected gain: **maint** (one sizing path) + **perf** (no duplicate RO, no extra definition rebuild on sub-pixel wobble). Risk: managing `innerWidth`-dependent decimation without `width` state requires responsive `defineChart((ctx)=>spec)` builder. Verification: screenshot outer width unchanged; bench M1a stable.

4. **Stabilize `xForIndex` via stashed ChartScale** — What to change: capture `xScaleD3Ref` via custom `ChartScale.resolve` (pattern `migrated/charts/composed-chart.tsx:501-546`) instead of recomputing linear time ratio from first/last dates. What it becomes: `xForIndex` reads `xScaleD3Ref.current.map(xValue)` matching actual TanStack range including nice/margin. Expected gain: **design** (highlight band never drifts) + **perf** (no per-hover date arithmetic). Risk: adds 20-line `ChartScale` wrapper. Verification: QA hover band pixel at n=1000 vs bklit; no drift after margin prop change.

5. **Gate decimation at bench `n` threshold** — What to change: `renderData` memo returns `data` directly when `data.length <= 100` (or `innerWidth` below threshold); otherwise LTTB. What it becomes: `if (data.length <= 64) return data;` short-circuit per `decimate-time-series.ts:88` floor. Expected gain: **perf** (avoid O(n log n) LTTB at small n where path cost is trivial; inventory §4 overhead #9 notes bench n=100 cost may dominate). Risk: diverges from bklit shell which decimates even at n=100; verify QA parity. Verification: bench parse+path at n=100 vs n=1000 before/after; screenshot diff <0.5%.

6. **Remove duplicate y-domain nice call** — What to change: compute `nicedYDomain` once and reuse for both `definition` `y.scale` domain and `YAxisOverlay` prop, instead of two independent `scaleLinear().domain().nice()` chains. What it becomes: single `const niced = scaleLinear().domain(yDomain).nice().domain()` passed to both. Expected gain: **design** (Y ticks guaranteed aligned with grid lines) + **maint** (one source of truth). Risk: none. Verification: Y tick label vs grid line pixel diff zero at mixed-sign domain.
