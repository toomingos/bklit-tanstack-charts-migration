# Area Audit — migrated/charts/area-chart.tsx

## 1. Summary
Migrated Area is a stacked-time area chart built as `areaFill` (custom `createMark` fill) + `lineY` (stock boundary stroke) per series inside a TanStack `defineChart` → `<Chart>` shell — the most faithful port of bklit's `Line` family, sharing its decimation, y-domain, hover, and reveal machinery with minimal divergence. The split is ~45% TanStack-native (two marks per series, `scaleUtc`/`scaleLinear` spec, `focus:'group-x'` + `animate` conditional) vs ~55% custom (manual `ResizeObserver`, `areaFill` heap optimization, `XAxisOverlay` HTML ticks, imperative `attachHoverChrome` with highlight band). Overall overhead verdict: **moderate, largely justified** — `areaFill` avoids a documented G4 heap ceiling breach, while the remaining HTML overlay / hover chrome duplication mirrors Line's retained cost and is the primary remediation surface.

## 6. Prioritized remediation candidates

1. **Remove `areaFill` heap clone if G4 headroom allows; use stock `areaY`** — What to change: replace `areaFill(renderData,{id:..., x,y,curve,fill})` with `areaY(renderData,{id:dataKey, x,y, y1:0, curve, fill: gradientUrl})` and drop `migrated/charts/internal/area-fill-mark.ts`. What it becomes: stock mark with same `path` but TanStack-owned point lifecycle. Expected gain: **maint** (95 lines removed, one fewer custom mark) — **design/perf neutral** if G4 passes. Risk: G4 heap at n=1000 would regress +~10-19% (header `area-fill-mark.ts:4` 4.45MB vs 3.74MB). Verify post-TanStack `areaY` improvements haven't already reduced heap.
