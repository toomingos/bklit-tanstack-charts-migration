# Gauge Chart Audit — migrated/charts/gauge.tsx + internal/gauge-*.ts (arc + linear)

## 1. Summary
Arc path is TanStack-native (`polar()` + two `radialArc` marks via `defineChart` + `renderChartSvgWithResources` for theme gradient) with correct `FOCUS_DISABLED` suppression; linear path is disclosed plain-`<svg>` fallback with zero TanStack marks — the docs-cited "slot position `i*(slotWidth+gapWidth)` has no cartesian domain" escape clause reused from ring/pie. Reveal is a single generic `seen`-Set reconciler covering mount + `totalNotches`/`value` updates. Split arc 70% TanStack-native / linear 10% TanStack-native. Overall overhead verdict: **arc low-moderate, linear low** — shared notch geometry + `CenterStat` reuse keep cost down, but dual `ResizeObserver` + dual `revealTiming` duplication add retained weight.

## 6. Prioritized remediation candidates
1. **What to change:** Fix linear `useLayoutEffect` dep array. **What it becomes:** `useLayoutEffect(()=>{...}, [geometry, geometryScrubbing, prefersReducedMotion, enterTransition, enterStaggerScale])` with stored `seenBgRef/seenActiveRef` not recreated per tick. **Expected gain:** perf — eliminates per-render `onPostPaint` re-arm during live value ramps, avoids `seen` double-insert. **Risk:** low. **Verification:** live `value` ramp 0→100 over 2s, assert `reconcileGaugeReveal` anim count equals `activeNotches` growth increments only, not `value` ticks where `data.length` unchanged; bench M1a not regressed.
2. **What to change:** Remove or wire `computeArcNotches` for arc path. **What it becomes:** Either delete dead `computeArcNotches` or make arc `bgRows/activeRows` derive from it so geometry has single source of truth. Map `ComputedNotch.points` → `startAngle/endAngle` via existing angle math or keep `computeArcNotches` as the math owner. **Expected gain:** maint — eliminates drift between `gauge-notch.ts` angle math and inline `gauge.tsx:395-470` copy. **Risk:** low — math already duplicated; test that TanStack `startAngle/endAngle` channels match `createNotchPath` quadrangle equivalence at parity check. **Verification:** `gauge-notch.ts` unit test of `computeArcNotches` angles vs inline, QA snapshot unchanged.
3. **What to change:** Harden arc `radialArcGroups[1]=activeGroup` selector. **What it becomes:** Query `marksGroup.querySelector('[data-ts-key="gauge-active"]')` or pass explicit `id` through TanStack key so selector is semantic not positional. **Expected gain:** maint — survives TanStack mark reorder. **Risk:** low — depends on TanStack emitting `id` as `data-ts-key`. Verify via DOM dump of `marksGroup.innerHTML`. **Verification:** add a third mark temporarily, assert selector still finds correct group.
4. **What to change:** Warn when `children` defs dropped on arc. **What it becomes:** `if (orientation==="arc" && defsChildren.length>0) console.warn("[gauge] custom <defs> children only honored on linear orientation")` (once, via ref). **Expected gain:** design — surfaces silent pattern drop to consumer instead of solid-fill mystery. **Risk:** none. **Verification:** render arc gauge with `<PatternLines>` child, assert warn fires once, no warn on linear.
5. **What to change:** Extract shared arc/linear `revealTarget` collection into `useGaugeReveal` hook. **What it becomes:** Hook owns `seenBgRef/seenActiveRef/revealAnimationsRef/renderGenRef` + `trackRevealFactory`, callers supply `queryTargets:()=>GaugeRevealTarget[]`. **Expected gain:** maint/perf — removes 70-line duplication, single `onPostPaint` helper, consistent `transformOrigin` handling. **Risk:** medium — refactors both orientation paths. **Verification:** arc + linear bench scenarios pixel-identical before/after, M1a timing within 5%.
