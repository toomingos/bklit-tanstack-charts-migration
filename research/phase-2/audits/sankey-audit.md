# Sankey Audit — Phase 2 Step 0.3

## 1. Summary (2-3 sentences: TanStack-native vs custom split, overall overhead verdict)

No stock TanStack Sankey mark exists (`research/phase-2/inventory/02-tanstack-charts-inventory.md` §Sankey gap), so `createSankeyMark` (`migrated/charts/internal/sankey-mark.ts:36`) via `createMark` + app-run `d3-sankey` `computeSankeyLayout` (`migrated/charts/internal/sankey-layout.ts:68`) inside `defineChart({ marks:[sankeyMark], x:null, y:null, guides:false, margin })` → `<Chart>` is the sanctioned GAP path, but hover is element-level `mouseenter`/`mouseleave` on cached `SVGGElement`/`SVGPathElement` arrays (`migrated/charts/internal/sankey-hover-chrome.ts:124`), tooltip is cursor-following `position:fixed` via global `window mousemove` (`migrated/charts/sankey-chart.tsx:507`), and reveal/labels/gradients are imperative `onRender` injections (`migrated/charts/internal/sankey-animation.ts:27,50,63,183`) outside TanStack's `points`/`animate`/`tooltip` pipeline. Overall overhead verdict: **moderate — justified GAP core, but high chrome duplication** — the single custom mark is correct and the only viable TanStack extension (`research/phase-2/tanstack-native/00-README.md` §SVG pipeline custom-mark boundary), yet surrounding `ResizeObserver` sizing, `window`-level pointer tracking, and WAAPI reveal reimplement host interaction/animation that TanStack could own with less DOM-coupling and better interruption semantics.

## 6. Prioritized remediation candidates (numbered, each with: What to change → What it becomes → Expected gain (perf/design/maint) → Risk → Verification via bench/QA gate)

1. **What to change:** Emit `ChartPoint` per node/link at centroid/polyline midpoint from `createSankeyMark.render` (`points: [{key:"sankey:node:0", x: (x0+x1)/2, y:(y0+y1)/2, datum:node, group:category}, ...]`), and replace `nodeElementsRef`/`linkElementsRef` + `attachSankeyHoverListeners` + `window mousemove` with `defineChart(mark, { focus: custom SankeyFocusStrategy using `computeNodeHoverConnected`, tooltip:{anchor:'point', placement:'auto'} })` + `onFocusChange(point)` → `setTooltipData` + coordinate-free `applySankeyHoverStyle` driven by `point.key`.
   **What it becomes:** TanStack-native hover via `mountChartRenderer` `handlePointerMove → pointsAtPointer → resolvePointerFocus → updateFocus → paintFocus` (`research/phase-2/tanstack-native/04-interactivity.md` §Pointer pipeline) with a single container-scoped listener and `samePointIdentity` dedupe, not per-element listeners.
   **Expected gain:** Perf (single delegation path, rAF-coalesced) + maint (deletes ~160 lines of element-ref/attach boilerplate) + design (tooltip anchoring via `placeTooltip`, not cursor `fixed`).
   **Risk:** M — custom `ChartFocusStrategy` must reimplement connectivity-aware grouping (`group` returns 1-hop neighborhood as `ChartPoint[]` for `onFocusGroupChange` highlight); label dim would still need imperative `style.opacity` since labels are outside `SceneNode`s unless they become `text` scene nodes.
   **Verification:** Pointer hover QA (node/link highlight + tooltip `formatValue` parity) + `grep -n "attachSankeyHoverListeners\|window.addEventListener.*mousemove" migrated/charts/sankey-chart.tsx` should be 0 after.

2. **What to change:** Forward sizing to TanStack host — remove `chartBounds` `useLayoutEffect` single-measure and render `<Chart width={undefined} aspectRatio={2} initialWidth={640}>` with `computeSankeyLayout` consuming TanStack `scene.chart` bounds via a `useEffect` on `adapter.getScene()?.chart` or by moving layout into `createSankeyMark` exclusively (no `layout` prop), deleting the dual-layout fallback.
   **What it becomes:** Responsive definition from `ctx.width/height` (`research/phase-2/tanstack-native/01-load.md` §Size resolution), restoring `prerender()` SSR path and live `ResizeObserver` without ad-hoc measure.
   **Expected gain:** Perf (M1a SSR first-paint with margins) + design (bounds never drift between component and mark).
   **Risk:** M — `d3-sankey` layout is expensive at large graphs; moving it fully into `createMark.render` runs it during `runtime.render` which is already the layout phase — should stay flat.
   **Verification:** SSR HTML snapshot contains `<svg>` without JS + resize QA (width 600→1200 preserves margins) + `grep -n "setChartBounds\|getBoundingClientRect" migrated/charts/sankey-chart.tsx` should be 0.

3. **What to change:** Replace label/gradient injection with declarative `SceneNode`s — have `createSankeyMark.render` return `text`/`label` scene nodes for `injectSankeyLabels` content and `defs` resources for gradients, removing `injectGradientDefs`/`injectSankeyLabels`/`injectLabelCssTransitions` imperative trio and `gradientDataRef` side-channel.
   **What it becomes:** `SceneNode[]` `key`ed by `sankey:label:${index}` reconciled via `reconcileChartSvg` enter/exit tweens; `SceneNode.style.opacity` already carries the `0.18s` transition.
   **Expected gain:** Maint (3 injection functions → 0; hover label dim becomes CSS on scene nodes, not `querySelector` per hover) + design (labels participate in `animate` lifecycle).
   **Risk:** M — `text` scene node lacks bklit's per-node `value` suffix flex layout; verify `text` anchor/offset props cover `horizontal` vs `vertical` rotated cases before removing imperative path.
   **Verification:** Screenshot diff at `labelOrientation:"vertical"` + hover bench (label opacity) + `grep -n "injectSankeyLabels\|injectGradientDefs" migrated/charts/sankey-chart.tsx` should be 0.

4. **What to change:** Scope `mousemove` to `containerRef.current.addEventListener('pointermove', ...)` and derive `mousePos` from `clientX/clientY - rect.left` only when `tooltipData` non-null; or remove `mousePos` entirely by anchoring tooltip to `ChartPoint.x/y` via `onFocusChange`.
   **What it becomes:** Container-scoped pointer tracking, no global `window` listener.
   **Expected gain:** Perf (no re-render on every window pixel).
   **Risk:** L.
   **Verification:** `grep -n "window.addEventListener.*mousemove" migrated/charts/sankey-chart.tsx` should be 0 after; pointer outside chart no longer churns `mousePos`.

5. **What to change:** Unify `displayName` extraction → `CHART_ROLE` Symbol walk and deduplicate `computeDisplayValue` (single export from `sankey-animation.ts` shared by `createHoverHandlers`).
   **What it becomes:** ` (child.type as RoleCarrier)[CHART_ROLE] === "sankeyLink"` alongside other charts (`migrated/charts/children.tsx:24`).
   **Expected gain:** Maint (uniform children contract) — see also heatmap item 5.
   **Risk:** L.
   **Verification:** `grep -rn "displayName" migrated/charts/sankey*` should be 0 after.
