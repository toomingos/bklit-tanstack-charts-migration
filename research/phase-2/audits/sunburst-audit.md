# Sunburst Audit — Phase 2 Step 0.3

## 1. Summary

One `polar({ radiusRatio:1, marks:[radialArc(arcRows, { fill, generator: custom arc() })] })` → `defineChart({ guides:false, x:null, y:null, focus:focusDisabled })` → `<Chart width={size} height={size}>` is TanStack-native after the D102 redo, but hover grow/dim, reveal (ring-staggered 1100 ms, 64-sample `d` keyframes), and zoom (750 ms, 30-sample `d` keyframes via `transitionGeometry`) are all WAAPI-imperative outside `reconcileChartSvg`, and depth opacity is baked into `fill` strings because `radialArc` offers no per-datum `fillOpacity` channel. Overall overhead verdict: **moderate** — the single-mark polar pipeline itself is clean and correctly uses TanStack scales/layout, but the surrounding WAAPI layers and React-state zoom orchestration duplicate what `animate:true` + definition identity could own, adding maintenance cost and a deferred-focus hazard for modest bench M1a fidelity gain.

## 6. Prioritized remediation candidates

1. **What to change:** Replace WAAPI zoom with synchronous definition swap — remove `zoomT`/`prevFocusId`/`zoomGen`/`zoomAnimationsRef` and have `zoomTo(nextId)` immediately call `setInternalFocusId(nextId)` (or `onFocusChange`) so `arcRows` derives from the new `focus` and TanStack reconciles via `animate:{duration:750, easing:'cubic-bezier(0.22,1,0.36,1)'}`; drop `buildZoomKeyframes` and the 750 ms CSS `d` tween in favor of `reconcileChartSvg` path tweening.
   **What it becomes:** TanStack `animate`-driven zoom (`research/phase-2/tanstack-native/00-README.md` §Animation; `reconcile.ts:157` attribute tween + `renderer.ts:958` reason=update check) — same path as `04-migrated-inventory.md` recommendation for sunburst.
   **Expected gain:** Perf (no second animation layer, interruptible by definition change) + maint (removes ~140 lines of zoom orchestration + `transitionGeometry` 30-sample loop) + design (eliminates deferred-focus hazard where breadcrumbs/trail lag behind visual).
   **Risk:** H — `transitionGeometry` encodes bklit's `DRILL_CENTER_SCALE`/`DRILL_CENTER_DEPTH_SHRINK` easing not captured by linear `d` interpolation; screenshot diff expected on drill-down arcs. Mitigate by keeping `transitionGeometry` as a `polar` custom `generator` helper if parity fails.
   **Verification:** Pointer click drill-down QA (rapid double-click not garbling) + bench `focusId` update latency + `grep -n "zoomT" migrated/charts/sunburst-chart.tsx` should be 0; screenshot diff for center radius during zoom.

2. **What to change:** Unify reveal under TanStack `animate` or gate `bkmRevealed` on `data` identity — check `revealSignature`/`data` in `handleRender` and clear `data-bkm-revealed` when `arcs` identity changes; or remove WAAPI reveal entirely and set `animate:{duration:1100, easing:'cubic-bezier(0.85,0,0.15,1)'}` on the definition with a `key: (d)=>`sunburst-arc-${d.arcIndex}`` so `reconcile.ts:138` `addEnterTween` opacity + path enter covers the same stagger.
   **What it becomes:** One animation system instead of WAAPI + TanStack reconcile.
   **Expected gain:** Maint + bench settle correctness (bench `onPhaseChange` currently uses `maxDelay+1100+935` deadline timer `sunburst-chart.tsx:531` instead of TanStack's animation completion).
   **Risk:** M — 64-sample `d` sampling was the D51 fix for discrete `d:none` interpolation; TanStack `d` tween may still discretely jump on large angular sweeps. Validate on 12-segment ring.
   **Verification:** Bench M1a settle (phase `ready` after mount) + `data` swap re-reveals + `grep -n "data-bkm-revealed" migrated/charts/sunburst-chart.tsx` should be 0 if unified.

3. **What to change:** Adopt TanStack `focus` for hover (custom `ChartFocusStrategy` that resolves nearest `ArcDatum` by polar distance, mapping `hoveredArcIndex` through `onFocusChange`) and remove positional `sortedArcs[i] ↔ els[i]` coupling in favor of `Map<arcIndex, SVGPathElement>` keyed by `data-ts-key` attribute.
   **What it becomes:** `defineChart(def, { focus: sunburstFocusStrategy, maxFocusDistance: 12 })` with `onFocusChange(point)` → `setInternalHoveredIndex(point.datum.arcIndex)` (`research/phase-2/tanstack-native/04-interactivity.md` §Custom focus strategies).
   **Expected gain:** Perf (pointer lookup becomes TanStack's scene `points` path, not DOM queries) + reliability (key-based, not positional).
   **Risk:** M — polar hit-testing has no native `scene.points` for `radialArc`; a custom mark would need to emit `ChartPoint` with `x/y` at arc centroid. Worth scoping to `buildArcs` → `points` emission before committing.
   **Verification:** Pointer hover bench (tooltip/hover parity) + unit test that `els` map not positional after definition reorder.

4. **What to change:** Migrate `isChildOfKind`/`classifyChildren` to `CHART_ROLE` Symbol walk and delete the unused `SunburstHoverCoordinator`/`SunburstSliceHoverRuntime` exports.
   **What it becomes:** ` (child.type as RoleCarrier)[CHART_ROLE] === "sunburstSegment"` pattern per `migrated/charts/children.tsx:24`.
   **Expected gain:** Maint (uniform children contract).
   **Risk:** L.
   **Verification:** `grep -rn "displayName" migrated/charts/sunburst*` should be 0 after.

5. **What to change:** Correct `padAngle` to bklit `0.015` and `hint` trail spacing to single spaces, or document as intentional parity waivers.
   **What it becomes:** `padAngle 0.015` and `trail.join(" › ")` single-space.
   **Expected gain:** Design (pixel/text snapshot parity).
   **Risk:** L.
   **Verification:** Screenshot + DOM text snapshot diff vs bklit fixture.
