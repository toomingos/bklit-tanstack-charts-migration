# Ring Chart Audit — migrated/charts/ring-chart.tsx

## 1. Summary
TanStack-native `polar()` with 2× `radialArc` per ring (track + progress) via `defineChart`/`Chart` owns all SVG emission; custom WAAPI expands + sweeps and imperative `scale(1.03/1.02)` spring hover are layered on `data-ts-key` queried groups. Split ≈60% TanStack-native / 40% custom (hover `settleAtRest` gate, two-phase stagger). Overall overhead verdict: **moderate-high** — two WAAPI anims per ring (8 at n=4) plus debug `console.log` left in hot path; hover handoff gate is correct but opaque.

## 6. Prioritized remediation candidates
1. **What to change:** Strip debug `console.log` from `ring-hover-chrome.ts`. **What it becomes:** Remove lines `84,100,112` (or guard behind `process.env.NODE_ENV !== "production"`). **Expected gain:** perf — removes per-paint string formatting + devtools side-effects on hover hot path; bench M2 (hover) noise reduction. **Risk:** none. **Verification:** grep `console.log` after patch shows 0 hits in `migrated/charts`; hover still works in `bench/ring` pointer probe.
2. **What to change:** Fix `bkmRevealed` one-shot into `Set<number>` diff like gauge. **What it becomes:** `seenTracks: Set<number>` + `seenProgress: Set<number>`; animate only unseen ring indices on each `handleRender`. **Expected gain:** design — n-grow animates new rings; matches gauge `reconcileGaugeReveal` and bklit `revealEpoch`. **Risk:** low — gauge pattern shipped. **Verification:** mount n=2, grow to n=4, assert 2 new WAAPI `scale` anims + 2 new `d` sweeps at probe delay.
3. **What to change:** Invalidate `ringElementMapRef` on `data.length` change (or recompute inside `useLayoutEffect` before arming hover). **What it becomes:** Move `querySelector([data-ts-key])` loop into `useLayoutEffect` so hover always queries live DOM after reconcile. **Expected gain:** maint — removes stale-cache class of bug for n-grow and `progress>0.001` toggle. **Risk:** low — adds one query pass per structural change (N≤8 typical, negligible). **Verification:** grow/shrink bench data, assert hover scale still fires on new ring.
4. **What to change:** Remove global `ringCleanupMap`; keep cleanup closured locally. **What it becomes:** Local `Map` inside effect, cleared in effect return — same as pie fix. **Expected gain:** maint — single cleanup path, no cross-instance state. **Risk:** low. **Verification:** mount/unmount 50×, event listener count stable.
5. **What to change:** Align resize animation: disable TanStack `animation` for ring resize or ensure reveal WAAPI uses `fill: none` so TanStack tween owns resize. **What it becomes:** Pass `animate: { resize: false }` or set `definition` `animate` false during resize, so only one writer drives `transform`/`d`. Document that `handleRender` reveal is mount-only and resize is TanStack tween. **Expected gain:** perf — avoids double-driven `d` during resize (WAAPI `fill: backwards` + `reconcile.ts:150` rAF). **Risk:** medium — check `renderer.ts:566` `resolveAnimation` respects `animate.resize`. **Verification:** trigger `ResizeObserver` resize, profile rAF count and computed `d` stability; no visual seam.
