### Pie — P9 (the real remaining work)

Confirmed current state: `showcase/migrated/charts/pie-chart.tsx:242` — `const { width, height } = useMeasuredRect(containerRef, !fixedSize);`. `useMeasuredRect` (`internal/use-container-size.ts:165-191`) is **undebounced** — its `ResizeObserver` callback commits every measured size immediately via `setMeasured`, no timer, no epsilon on the *initial* commit (subsequent commits do apply the 0.5px epsilon, but there's no 10ms coalescing window at all). Ruling: *"ACCEPT — foundation consolidation; FIX-cheap note"* (`synthesis/parity.md:112`) — low severity, but cheap enough that go-to-plan.md charters it as a real FIX here rather than leaving it ACCEPTed.

Swap `pie-chart.tsx:242` from `useMeasuredRect(containerRef, !fixedSize)` to `useDebouncedContainerSize(containerRef)` (`internal/use-container-size.ts:108-153` — 10ms debounce + 0.5px epsilon on every commit, matching bklit's `ParentSize debounceTime={10}` exactly, same as gauge's `:381` call site).

**A real signature mismatch you need to resolve, not just a rename:** `useMeasuredRect` takes an `enabled` second argument (`useMeasuredRect(containerRef, enabled = true)`) that pie currently uses to skip mounting a `ResizeObserver` entirely when `fixedSize` is set (`!fixedSize` passed as `enabled`). `useDebouncedContainerSize` has **no second parameter** — it always observes whatever `containerRef` points at. Before assuming this is a problem: check `pie-chart.tsx`'s render — `containerRef` is attached via `ref={containerRef}` on **both** the fixed-size and responsive-size render branches (`pie-chart.tsx:748` and `:761`), so a container element exists to observe in either mode already; the `enabled` flag was purely an *optimization* to skip an unnecessary observer, not something that changes correctness (the computed `size` already falls back to `fixedSize ?? Math.min(width, height)`, so an extra harmless observed value in fixed mode never gets used). Confirm that reasoning against the actual render output before committing to the swap — if it holds, a straight swap to `useDebouncedContainerSize(containerRef)` with no `enabled` equivalent is correct and you're only losing a micro-optimization, not behavior. If you find a real behavioral difference (e.g. the fixed-size branch renders a different DOM node than the responsive branch such that the "always observe" assumption breaks), stop and report it rather than silently adding an `enabled` parameter to the shared hook (that would touch gauge's already-working call sites too — a shared-hook signature change is bigger blast radius than this package's stated scope).
