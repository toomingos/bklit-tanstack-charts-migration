## LEAD CORRECTION — read this before doing anything else

`go-to-plan.md:245` states the alias layer is *"zero-pixel by design."* **That is false as written, and a one-line CSS alias will NOT achieve zero drift.** Verified from the clone at HEAD:

`showcase/repos/tanstack-charts/packages/charts-core/src/scene.ts:58-71`
```ts
export const defaultChartTheme: ChartTheme = {
  ...
  palette: [
    'var(--ts-chart-1, #2563eb)',
    'var(--ts-chart-2, #f97316)',
    'var(--ts-chart-3, #10b981)',
    'var(--ts-chart-4, #8b5cf6)',
    'var(--ts-chart-5, #ec4899)',
    'var(--ts-chart-6, #06b6d4)',   // <-- SIXTH ENTRY
  ],
}
```

The native palette has **six** entries. Every migrated part that would adopt it cycles **five**:

| part | constant | site |
|---|---|---|
| pie | `defaultPieColors` | `pie-chart.tsx:87` (`var(--chart-1..5)`) |
| sunburst | `defaultSunburstColors` | imported at `sunburst-chart.tsx:62`, cycled at `:375`, `:383` |
| sankey | `DEFAULT_COLORS` | `sankey-chart.tsx:133` — note these carry **literal fallbacks**, `var(--chart-1, #7c3aed)` |
| scatter | `DEFAULT_SCATTER_COLORS` | see `research/phase-4/scatter.md:57` |
| ~~choropleth~~ | ~~`DEFAULT_CHOROPLETH_COLORS`~~ | **STRUCK — this row was WRONG (D260).** `choropleth-chart.tsx:135-141` cycles `var(--chart-scale-01..05)`, a separate **sequential** token family (`showcase/app/globals.css:134`/`:205`) matching legacy (`repos/bklit-ui/.../chart-scale.ts:3`) — not the categorical `--chart-N` set. T-D15's 6-vs-5 premise does not apply. Routing it through `CHART_CATEGORY_PALETTE` would reintroduce a token deviation that is already fixed. **Do not touch choropleth in this package.** |

Both cycle by index. With a 6-long native palette vs a 5-long legacy palette:

- indices 0–4 agree (given the alias),
- index 5: native → `--ts-chart-6` (no `--chart-6` exists → falls back to `#06b6d4`, cyan); legacy → `--chart-1`. **Diverges.**

And aliasing `--ts-chart-6: var(--chart-1)` does **not** rescue it. A 6-long cycle `[c1,c2,c3,c4,c5,c1]` against a 5-long `[c1..c5]` agrees at i=5 (both `c1`) but diverges at **i=6** (`c1` vs `c2`) and stays out of phase forever after. **Cycle length is the defect, not token naming.**

This matters at every gate density in the package: pie and scatter gate at `--n 1000`, sankey at 33, sunburst at 27 — all far past 6 categories.

### Required approach

Do **not** rely on `defaultChartTheme.palette` for these five parts. Pass an explicit **5-entry** palette through the chart's theme override so cycle length is preserved:

```ts
theme: { palette: ['var(--chart-1)', 'var(--chart-2)', 'var(--chart-3)', 'var(--chart-4)', 'var(--chart-5)'] }
```

Confirm the override path before writing five copies of it — `scene.ts:301-306` and `facet.ts:814` both resolve `spec.theme?.palette ?? theme.palette`, and `runtime.ts:22` resolves `options.defaultTheme?.palette`. Prefer **one** shared constant in `internal/design-tokens.ts` over five per-chart literals; that also sets up T-C10's token consolidation.

Preserve sankey's literal fallbacks (`var(--chart-1, #7c3aed)`) exactly — dropping a fallback is a silent behavior change wherever the token is undefined.

Whether a `--ts-chart-N` alias block is *also* wanted is a separate question: native surfaces that are not the categorical palette (e.g. `crosshair.ts:195,229` use `--ts-chart-crosshair-*`) read their own tokens. Add an alias block only if you find a native surface actually consuming `--ts-chart-1..6` in these five parts; if you add one, say exactly which surface required it.
