## Cross-reference constraints — read before doing anything else

### The reveal-replay invariant (mandatory, verbatim from cross-referenced evidence)

Reveal must replay **on mount and on `playKey` change — never on hover, resize, or any other re-render.** This is enforced entirely by in-memory ref identity, not DOM state, because TanStack's SVG reconciler (`syncAttributes` in `showcase/repos/tanstack-charts/packages/charts-core/src/reconcile.ts`) strips every DOM attribute not present in fresh markup on every reconcile — including custom `data-bkm-*` stamps. A hover-triggered definition change (hover-grow recompute) forces TanStack to re-diff the stage `<svg>` from fresh markup, wiping any `data-bkm-revealed`-style stamp a naive implementation might compare against — and if reveal-gating compares against that stamp, hover retriggers the full 1100ms+ reveal on every pointer move. This exact regression is D251/F1 (Wave 1, root-caused and fixed on sunburst).

The current fix (`sunburst-chart.tsx:400-402`) keeps two guards **in refs**, immune to reconcile-driven DOM stripping:
- `playCycleRef` (line 400, `useRef<string>(`${playKey}`)`) — identifies the current reveal "cycle." Only a `playKey` prop change advances it.
- `seenRevealedRef` (line 402, `useRef<Set<number>>(new Set())`) — tracks which `arcIndex` values have already played their reveal within the current cycle.

`handleRender` (lines 575-639) runs on every TanStack render — including hover-driven ones — but its `svgForBkm.dataset.bkmRevealed === "1"` check (line 606) is only a fast bail-out for the settled steady state, not the replay-identity check itself; identity lives in `seenRevealedRef`/`playCycleRef`. Inline comment at 597-604 documents exactly why: comparing a dataset stamp there fired on every hover and cleared `seen`, replaying the full reveal on each pointer move — this was the Wave-1 regression.

Replay itself is driven by a separate effect (`sunburst-chart.tsx:995-1028`, "SB1: playKey replays the initialization animation") that fires **only** on `playKey` change (line 996 bails if unchanged), and on firing: cancels in-flight reveal animation, clears timers, clears `seenRevealedRef`, deletes the `bkmRevealed`/`bkmLabelsRevealed` DOM stamps, resets label opacity, and imperatively re-drives arcs+labels via `handleRenderRef.current?.()` (line 1027) — because the chart *definition* is unchanged on a `playKey` bump alone, so TanStack's own `onRender` won't refire by itself.

**Consequence for T-D12**: any native swap of the reveal/timing layer must preserve this two-guard, ref-identity architecture. A native reveal primitive that gates replay via a DOM data-attribute comparison will silently reintroduce D251/F1. This is undetectable by a settled-only QA gate — the visual end-state is byte-identical whether reveal replays correctly (mount/`playKey` only) or incorrectly (every hover). That is exactly why the gate below mandates hover captures.
