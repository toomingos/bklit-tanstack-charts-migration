## Correction — `ChartBrush` is genuinely live, not dead code, despite looking orphaned via static grep

Verified directly: a plain grep for `<ChartBrush` or `ChartBrush}` JSX usage inside `showcase/migrated/charts/*.tsx` returns **zero hits** — no chart file statically renders `<ChartBrush>` as a JSX literal. This can look like dead/orphaned code on a naive static-import audit. **It is not.** `internal/chart-brush.tsx:37` stamps `(ChartBrush as unknown as Record<symbol, unknown>)[CHART_ROLE] = "brush"` (the same `Symbol.for("migrated.chartRole")` convention used by `Line`/`Area`/`Bar`/etc., defined at `children.tsx:35`). `line-chart.tsx` and `area-chart.tsx` extract a `brushes` array from their own JSX children by role (`children.tsx:339`, `else if (role === "brush") out.brushes.push(child)`), then render whatever the **consuming application** passed as `<ChartBrush/>` children of `<LineChart>`/`<AreaChart>` inside a `BrushHostContext.Provider` (`line-chart.tsx:992-994`, `area-chart.tsx:1015-1018`). This is real, live composition — an app author writes `<LineChart>...<ChartBrush/></LineChart>`, invisible to a grep of `line-chart.tsx` itself, exactly the same CHART_ROLE pattern documented for other "orphan-looking" components elsewhere in this migration (see P3-01.md's template for the general pattern). **If any prior research report (e.g. an `internal-brush.md`-style document) frames `ChartBrush` as dead code, that framing is wrong — treat it as a live, actively-swapped component for this package.**

This is separate from and should not be confused with **`brush-layout.tsx`** (`BrushLayout`, 88 lines), which genuinely IS orphaned: it's re-exported from both barrels (`index.ts:335-338`, `internal/index.ts:174`) but has zero consumers anywhere in `showcase/migrated/charts/*.tsx` or `internal/*.ts(x)` beyond its own file and the barrel re-export lines — confirmed by direct grep. `brush-layout.tsx` is tanstack.md row 11, assigned to **P3.13**, not this package.
