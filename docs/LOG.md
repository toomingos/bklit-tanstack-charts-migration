## 2026-07-31 — Phase 2 start: ScatterChart (Fable decisions, Sonnet execution)

- **D14**: Scatter pre-migration review (Sonnet research, Fable-verified conclusions) and the resulting architecture decisions:
  - bklit scatter has **no clip reveal** — each marker is a framer `motion.g` entering with delay `(max(0, cx − visualExtent)/innerWidth) × 1.1s` + a fixed 0.5s opacity/blur(2px) tween on bezier(0.85,0,0.15,1); this per-node React/framer approach is why bklit mounts in 2817ms script at n=10k. Migrated port: TanStack renders circles once, reveal is imperative WAAPI per circle from `onRender` (delay computed, `fill: backwards`) — zero React in the animation.
  - bklit scatter is **undecimated** (renders all n×2 points; confirmed no `decimate-time-series` import) → migrated must NOT decimate either, or the comparison is dishonest and pixels diverge.
  - Hover selection is **x-bisect like line** (`useScatterChartInteraction`), NOT nearest-2D — so `focus: 'group-x'` + `maxFocusDistance: Infinity` again. NB: the *naive* `tanstack-scatter` baseline scenario leaves focus unset (2D nearest, 48px cutoff) — parity requires the explicit option.
  - Scatter dim/highlight ≠ line's: ALL markers dim to opacity 0.5 + blur(2px) at 0.15s while the tooltip is active, and the hovered point of each series gets an enlarged (scale 1.35) undimmed marker copy on top. Line's 0.3/0.4s path re-stroke band is structurally inapplicable (dots are circles, no path).
  - Default marker = fill circle r=5 PLUS same-color stroked ring at r=8 (strokeWidth 2, ringGap 2) → two TanStack `dot` marks per series (fill mark id=dataKey, ring mark id=dataKey+"__ring"); the hover chrome ignores non-series markIds by construction. TanStack's dot default r=3.5 must always be overridden.
  - x-range is inset by `max(radius)+10` px per side (bklit `xRangePadding`) — line has no such inset; needs a resolved-scale range override on the TanStack side.
  - ScatterChart has **no `status`/loading prop** (bklit hardcodes ready lifecycle) — migrated API must not inherit line's.
  - y-domain rule is scatter-specific: `[0, max*1.1]`, negatives silently ignored (bklit limitation, ported verbatim, not "fixed").
