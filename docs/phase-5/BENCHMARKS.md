## Verdict

1. **Matrix run:** 24/24 `--all`-matrix cells (`line`/`area`/`bar`/`scatter` × `bklit`/`tanstack` × `n∈{100,1000,10000}`) completed with real, non-substituted numbers. One cell (`tanstack/line n=1000`) was interrupted mid-run by a concurrent session killing the shared bench preview server; it was discarded (not reported) and re-run cleanly from scratch — the number in this report is from that clean re-run only.
2. **No errors, no `not-recorded` cells.** Every metric aggregate in every cell has `n=7` measured runs.
3. **M3a — the one channel §3 itself calls valid — shows no regression >20% anywhere in the matrix**, on either impl, at any density. This is the headline finding: on the one pre-upgrade-validated channel, the runtime upgrade (vendored source clone → published npm `@tanstack/charts@0.15.0`) shows no measurable interaction-cost regression.
4. **M1a/M1b flagged 4 cells, all on raw `tanstack`, all small-n, all on the channel §3 already rated VOID/unstable on this machine for three straight prior runs.** These are reported in full, not smoothed over — but per the project's own standing finding on this exact channel, they should not be read as a confident verdict on the upgrade without a fresh in-run control, which this pass did not capture (out of scope for what was asked: `--all` once, not `--all` twice for a same-session control).
5. **`bklit` (unaffected by the phase-5 runtime swap, included as an in-run sanity control) shows no flagged cell on any channel** — consistent with the four `tanstack` flags being upgrade-independent machine noise rather than a same-session-wide problem.
6. **M2c bundle size is a new, non-comparable baseline** — see the dedicated section above. Do not read anything into it beyond "here is what phase 5's build produces," per the task's explicit caveat.
7. **Overall: the runtime upgrade (5.0.1's move from a vendored TanStack Charts source clone to the pinned published `@tanstack/charts@0.15.0` + `@tanstack/react-charts@0.15.0` npm packages) shows no confidently-attributable performance cost.** The only flagged deltas sit on a channel this project has already independently established is not reliable on this machine, are small in absolute terms, and are not corroborated by the one channel rated reliable (M3a) or by the `bklit` control arm. Recommend: no regression ruling from this data alone; if a hard M1a/M1b answer is needed, re-run with a same-session `bklit` and/or repeat-`tanstack` in-run control per the D273 protocol before treating any of the four flagged cells as real.
