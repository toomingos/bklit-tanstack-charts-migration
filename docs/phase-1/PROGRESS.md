## Legend

**Status values**: `not started` → `in research` → `migrating` → `QA` → `benchmarking` → `approved` (all gates below pass) — or `blocked` (waiting on a decision/dependency; rationale goes in `docs/LOG.md`).

**QA gates** (research/05 §QA):
- **Q1 — Visual parity**: pixelmatch diff of `bklit` vs `migrated` screenshots at settled + interaction states. Gate: ≤ 0.5 % differing pixels per screenshot (≤ 5 % for mount-reveal animation frames).
- **Q2 — API compatibility**: fixture exercising all public props/callbacks typechecks (`tsc --noEmit`) against the migrated component with zero errors and zero runtime console errors.

**Benchmark gates** (research/05 §Benchmark gates; `B`=bklit baseline, `T`=native TanStack baseline, `M`=migrated):
- **G1 — Improvement**: `M` beats `B` on M1a/M1c/M2a/M3a/M3c, with ≥ 20 % improvement on M1a, M3a, M3c (north stars), no regression > 5 %.
- **G2 — Closeness** (waived if no native `T` exists): gap-closure ratio `(B−M)/(B−T) ≥ 0.6` on M1a/M3a/M3c.
- **G3 — Steady state**: M2a idle CPU ≤ 50 % of `B`'s, within 2× of `T`.
- **G4 — Memory/bundle**: M2b and M2c do not exceed `B` by more than 10 %.

A migration is **approved** only when Q1 + Q2 + G1–G4 all pass, from scripts, on the same run (research/05).
